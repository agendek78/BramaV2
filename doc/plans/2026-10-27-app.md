# Moduł `:app` — plan implementacji

> **Dla wykonawców agentowych:** WYMAGANY SUB-SKILL: superpowers:subagent-driven-development (zalecany) albo superpowers:executing-plans, zadanie po zadaniu. Kroki mają składnię checkboxów (`- [ ]`).

**Cel:** Aplikacja Android gotowa do użycia z płytką: ekrany Compose (główny, dodaj bramę QR/PIN, ustawienia, historia), usługa `connectedDevice` z powiadomieniem „brama w zasięgu”, CompanionDeviceManager, magazyny, spięcie `GateRepository` z `BleGateLink`.

**Architektura:** `BramaApp` ręcznie składa zależności i uruchamia `GateRepository`. UI i usługa tylko renderują `GateUiState` przez czyste mapery (testowane na JVM) i wołają intencje repozytorium. Kod zależny od urządzenia (Keystore, CDM, usługa, skaner) jest cienki i sprawdzany kompilacją.

**Stos:** Kotlin 2.2.10, AGP 9.2.1, Compose BOM 2026.02.01, Material 3, `navigation-compose` 2.10.2, `lifecycle-viewmodel-compose`/`lifecycle-runtime-compose` 2.11.0 (jak `lifecycleRuntimeKtx`), `datastore-preferences` 1.3.0, `play-services-code-scanner` 16.1.0, coroutines 1.10.2, JUnit 4.

**Specyfikacja:** `doc/app_design.md` (zatwierdzony), `doc/PLAN_I_SPECYFIKACJA_BRAMY.md` 1.4 (rozdz. 3 — dokładne teksty, 4, 7, 9.2–9.4, A27, A58, A70–A72), porty `domain/.../Ports.kt`, `doc/domain_design.md`, `doc/ble_design.md`.

## Ograniczenia globalne

- `minSdk = 34`, `compileSdk = release(37)`, `targetSdk = 36`, Java 11.
- Nowe zależności pobiera Gradle (internet dostępny). Pierwszy build bez `--offline`, kolejne mogą być `--offline`.
- Teksty UI z listy zamkniętej wyłącznie przez `Texts.text(UiMessage)`, dokładnie jak w spec 3. Nigdzie „Brama otwarta/zamknięta”.
- UI nie sięga do magazynów ani `:ble`: tylko `GateRepository` (stan + intencje).
- Sekrety (`K_client`, `K_setup`, PIN) nie trafiają do logów ani backupu; `allowBackup=false`, reguły backupu wykluczają wszystko.
- Pliki w `noBackupFilesDir`; zapis atomowy (plik tymczasowy + `renameTo`).
- Repozytorium bez git: zadanie kończy zielony test wskazany w zadaniu; pełny zestaw na końcu: `./gradlew :protocol:test :domain:test :ble:testDebugUnitTest :app:testDebugUnitTest :ble:assembleDebug :app:assembleDebug -q` bez ostrzeżeń kompilacji w nowym kodzie (z wyjątkiem udokumentowanych `@Suppress` dla API przestarzałego, a jedynego w minSdk 34).

## Punkty uwagi przy review

1. Restart telefonu przed pierwszym odblokowaniem: klucz Keystore niedostępny → `CredentialLoad.Locked`, bez wyjątku na zewnątrz i bez kasowania pliku → Zadanie 4, `keystoreUnavailableLoadsLocked`.
2. Uszkodzony plik poświadczenia lub historii — brak crasha. Poświadczenie: `CredentialLoad.None` bez kasowania pliku (`CredentialFileCorrupt` zapisany do diagnostyki); historia: złe linie pominięte → Zadanie 4, `corruptCredentialFileLoadsNoneWithoutDeleting`, `corruptHistoryLinesAreSkipped`.
3. Nieaktualne powiadomienie z przyciskami po zmianie stanu — model nigdy nie pokazuje akcji bez `notificationActionsAvailable` → Zadanie 5, `actionsOnlyWhenAvailable`.
4. Usługa zatrzymana w trakcie komendy po zamknięciu ekranu — decyzja „usługa potrzebna” uwzględnia komendę w toku → Zadanie 5, `serviceNeededWhileCommandInFlight`.
5. Odebrana zgoda na powiadomienia przy SHOWN — do domeny idzie `presenceDisappeared()` → Zadanie 8, `revokedNotificationPermissionHidesPresence`.
